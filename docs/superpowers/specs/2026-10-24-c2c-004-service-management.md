# C2C-004：GPT-SoVITS 本地服务管理设计

状态：设计与实现计划已获用户确认；实现及独立审查 PASS（2026-10-25）。

## 目标与范围

让工作室能够连接现有 GPT-SoVITS 服务，也能按明确请求启动、检测和停止自己管理的服务。
这一项交付为 C2C-005 的真实语音合成提供稳定入口；本轮不实现生成音频、训练或前端。

保留现有 FastAPI、配置、角色及模型注册行为，不修改上游安装、现有权重和训练产物。
启动业务后端时不自动启动推理服务。只有用户调用启动操作才加载推理进程。

## 考虑过的方案

1. 只连接手动启动的服务：改动小，但用户仍需管理额外进程。
2. 同时管理服务启停、状态和超时：补齐生命周期，需处理并发、进程归属及启动失败。

用户选择方案 2。建议保留连接外部服务的只读检测能力；工作室只停止自己启动且仍持有进程句柄的进程。

## 服务接口与状态

新增 `/api/tts/service` 下的状态、启动、停止操作：GET 状态，POST 启动，POST 停止。
启动和停止使用固定配置，不接受任意命令或解释器参数。

响应区分 stopped、starting、ready、unavailable、failed，并注明是否由工作室管理。
未由工作室启动的服务可以检测，但停止操作应返回明确的冲突结果，不能调用其远程退出接口。
重复启动不得创建多个进程；启动中再次请求必须幂等或明确返回冲突。

探测采用有超时和响应大小上限的只读 HTTP 请求，验证上游 OpenAPI 中的推理及权重切换路由，
不向 `/tts` 发送测试音频。进程存活与接口就绪分别判断。
状态只说明服务接口可用，不证明指定模型已加载或声音合成成功。

## 进程与配置

默认仅连接和绑定本机回环地址。复用已配置的 GPT_SOVITS_ROOT、GPT_SOVITS_PYTHON 和预训练资源路径。
启动命令以参数数组执行，使用上游 api_v2.py 的实际参数，不经 shell 拼接。

明确配置连接超时、启动等待期限及停止等待期限；超时、端口冲突、错误响应和提前退出均返回可定位结果。
日志写入项目运行输出目录，不混入训练任务文件。
只生成自己的运行配置，禁止覆盖上游 tts_infer.yaml；配置固定 v2Pro，使用当前已配置的本地资源。
本轮默认 CPU，以避免隐式 GPU 占用；后续真实合成任务再验证性能及设备选择。

管理器在单个业务进程内保存子进程句柄并串行化生命周期操作。
业务后端正常退出时回收自己启动的服务。多 Uvicorn worker 不受支持，README 必须说明单进程运行约束。
不得按进程名、PID 文件或端口批量终止系统进程。

## 验证与验收

- 临时假 HTTP 服务验证就绪探测、错误结构、无服务、超时与响应边界。
- 可控的测试子进程验证启动参数、提前退出、启动超时、重复启动和只停止自有进程。
- API 测试验证响应 Schema、状态变化、并发操作和异常映射。
- 原有测试在两套现有 Python 环境运行；检查模型和训练资源保留。
- 默认测试不启动真实 GPT-SoVITS，不下载模型，不训练。
- 若本轮进行真实服务启动验证，单独记录设备、耗时、结果并停止自己的进程；不把替身测试称为真实推理通过。
