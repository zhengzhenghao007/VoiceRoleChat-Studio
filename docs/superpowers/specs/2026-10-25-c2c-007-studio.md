# C2C-007 real frontend workbench

User authorized autonomous continued development. Codex selects a plain HTML,
CSS and JavaScript implementation extending the existing frontend; introducing
a framework/build system is unnecessary for this bounded workbench. FastAPI
serves it at /studio/ with same-origin API calls, preserving / and /health.
No package installation, remote fonts/assets, training UI or pretend chat.

## Product flow

Browse/create/edit persistent characters, inspect real model pairs, configure
a saved voice with model selection, reference WAV upload/path and prompt/language,
explicitly start/stop the CPU service, synthesize a short character audition and
play/download the actual result. Existing character metadata is preserved.
Conversation preference flags may be saved but clearly belong to future chat.

Navigation: Characters and Models. Desktop character view has a character list,
an editing form and a separate listening area; on narrow screens these stack.
No fake counts/status/content. Empty/loading/error states and retries are real.
Incomplete models are visible but cannot be selected for a new binding. Saved
unavailable bindings remain visible and can be replaced/cleared.

Save PATCH uses expected_revision and only changed fields. Unchanged missing
voice resources must not prevent editing the role name. Voice settings use
complete replacement, explicit clear only when disabled. Preserve entered data
on validation/conflict/connection errors; offer explicit reload after conflict.
Confirm before switching away from dirty edits. Disable conflicting actions
while a mutation is pending, and do not display late results as another role.
Upload fills reference path but does not silently save the role. No automatic
model loading on page open. External services remain read-only; busy/errors
display actionable text. Synthesis uses a saved role only; unsaved edits must
be saved first. Audio player/download use only generated local audio URLs.

## Visual direction (Codex decision)

A compact voice production desk, not a marketing landing page. Palette:
mist #eef3f6, paper #ffffff, ink #223645, deep blue #193c52, teal #196d79,
amber #a66d1d. Microsoft YaHei UI/PingFang SC/system fonts for local Chinese
legibility, restrained heading scale, left alignment. Borders separate editor
sections; no decorative gradient, invented waveform or generic metric cards.
The listening area is the memorable emphasis: one clear generate action and a
real audio player. Avoid equal cards and excessive chrome from the old prototype.

```text
brand + connection                    service state / start / stop
Characters | Models
character list | character + voice editor | audition text, action, player
```

Visible labels/focus, native controls, status live region, keyboard access,
reduced-motion support, desktop/mobile layout without horizontal overflow.
Never inject API strings through innerHTML or other executable markup.

## Acceptance

Backend tests verify static mount/assets and existing APIs. Headless Python
Playwright uses a temporary character/model/upload store and fake inference HTTP
with real FastAPI routes: create/edit/reload, bind/upload, start/stop, audition/
audio retrieval, model/empty/offline/validation/conflict states and mobile layout.
No browser test edits real user data or loads real models. Existing C2C-005
real CPU acceptance remains the inference evidence. Capture and visually inspect
desktop/mobile screenshots, check console failures. Run both backend suites.
ChatGPT reviews before authorized GitHub push. No role deletion, recording,
transcription, training or LLM conversations in this task.
